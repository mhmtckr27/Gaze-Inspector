Getting started

Since v1.0.0

Installing Gaze, and what ships with it.

Install

Gaze ships as a Unity package, and it is open source.

  • Unity Asset Store: import through Window → Package Manager → My Assets
  • GitHub: source, releases and issues

How Gaze takes over the Inspector

Gaze registers a single fallback editor:

[CustomEditor(typeof(Object), true, isFallback: true)]
[CanEditMultipleObjects]
public class GazeEditor : UnityEditor.Editor

Meaning:

  • A type with its own [CustomEditor] is untouched. Being a fallback means Unity only reaches Gaze when nothing else claims the type. Your existing custom editors keep working exactly as they did.
  • A property with a [CustomPropertyDrawer] keeps it. Gaze steps aside and lets that drawer render the property, so drawers you wrote and drawers that came with other packages behave exactly as they did.

To turn the whole thing off, untick Enable Gaze in the settings window. Every Inspector goes back to what Unity would draw without Gaze: your own [CustomEditor] where there is one, the default Inspector everywhere else.

Settings

Tools → Gray Wolf → Gaze → Settings opens a dashboard window:

Tab What it holds
General Enable Gaze, the master switch for the takeover described above
Appearance Page size for collections, and value foldout threshold for dictionaries
About Version, links and the demo scene

Settings are stored in ProjectSettings/GazeInspectorSettings.asset.

What’s in the box

  • Conditional fields: show, hide, enable and disable a field from another value
  • Field attributes: buttons, validation, labels, change callbacks, clamped vectors and curves
  • Serialized dictionaries: key/value pairs that actually save and actually edit
  • Custom drawers: draw your own types, or write your own attributes
  • Right-click menus: the property clipboard, and serving your own menu

Requirements
Unity 2022.3 or newer

Conditional fields

Since v1.0.0

Show, hide, enable and disable a field based on another field's value.

Reach for ShowIf/HideIf when an irrelevant field would be noise, and EnableIf/DisableIf when the reader still needs to see the value they can’t currently change.

Show field B when bool A is true

Name the other member. Use nameof so an IDE rename updates the attribute too:

using GrayWolf.Gaze;
using UnityEngine;

public class Spawner : MonoBehaviour
{
    [SerializeField] private bool useCustomRate;

    [ShowIf(nameof(useCustomRate))]
    [SerializeField] private float spawnRate = 1f;
}

Inversion

[SerializeField] private bool useCustomRate;

// Equivalent to [HideIf(nameof(useCustomRate))]
[ShowIf("!" + nameof(useCustomRate))]
[SerializeField] private float defaultRateNote;

Non-bool comparison

using GrayWolf.Gaze;
using UnityEngine;

public class Solver : MonoBehaviour
{
    public enum Mode { Simple, Advanced, Debug }

    [SerializeField] private Mode mode;

    [ShowIf(nameof(mode), Mode.Advanced)]
    [SerializeField] private float tolerance = 0.01f;

    [SerializeField] private int passes = 1;

    [EnableIf(nameof(passes), 1)]
    [SerializeField] private bool singlePassOptimisation = true;
}

The ! prefix works here too, and negates the comparison rather than the value: [ShowIf("!" + nameof(mode), Mode.Debug)] shows the field in every mode except Debug.

Another example

A condition can name a field, a property, or a parameterless method returning bool. The member may be private, may be static, and may be declared on a base type.

using GrayWolf.Gaze;
using UnityEngine;

public class Turret : MonoBehaviour
{
    [SerializeField] private Transform target;

    private bool HasTarget => target != null;

    [ShowIf(nameof(HasTarget))]
    [SerializeField] private float leadTime = 0.2f;

    private bool IsConfigured() => target != null && leadTime > 0f;

    [EnableIf(nameof(IsConfigured))]
    [SerializeField] private bool autoFire;
}

There is no And/Or combinator

Gaze conditional attribues has no Or/And logic, no params array of conditions, and no expression parser.

Two ways to express compound logic:

Stack different kinds. They are independent, and combine naturally:

[SerializeField] private bool advanced;
[SerializeField] private bool locked;

[ShowIf(nameof(advanced))]     // only visible in advanced mode…
[DisableIf(nameof(locked))]    // …and read-only while locked
[SerializeField] private int iterations = 4;

Put the logic in a property. For anything a single name can’t say, combine them in a property:

[SerializeField] private bool advanced;
[SerializeField] private int passes;

private bool ShowTolerance => advanced && passes > 1;

[ShowIf(nameof(ShowTolerance))]
[SerializeField] private float tolerance = 0.01f;

When a condition can’t resolve

If the named member doesn’t exist, isn’t readable as a bool, or is compared against an incompatible type, Gaze leaves the field visible and editable and draws an error box above it naming the problem.

An empty or whitespace-only condition string is reported the same way.

Hidden fields and their messages

A field hidden by ShowIf or HideIf also suppresses the message boxes contributed by the attributes it wraps:

[ShowIf(nameof(overrideDefaults))]                       // outer: suppresses…
[InfoBox("Overrides the automatic solver.")]             // …this box when hidden
[SerializeField] private float damping = 0.2f;

Field attributes

Since v1.0.0

Buttons, validation, labels, change callbacks and clamped values.

Reference

Attribute Applies to Does
[Button] Method Draws a button under the Inspector that calls the method
[Required] Field Error box while the field is empty
[InfoBox] Field Help box above the field
[ReadOnly] Field Draws the value, blocks editing it

Call a method from the Inspector

Tag any parameterless method. It may be private:

using GrayWolf.Gaze;
using UnityEngine;

public class Spawner : MonoBehaviour
{
    [SerializeField] private int count = 3;

    [Button]
    private void SpawnOne()
    {
        Debug.Log($"Spawning 1 of {count}");
    }

    [Button("Spawn All")]
    private void SpawnEverything()
    {
        Debug.Log($"Spawning {count}");
    }
}

Without a label, the button is named from the method with the words split out. SpawnOne becomes “Spawn One”.

Flag a field that must be filled in

using GrayWolf.Gaze;
using UnityEngine;

public class Weapon : MonoBehaviour
{
    [Required]
    [SerializeField] private string displayName;

    [Required("Assign the muzzle transform before entering play mode.")]
    [SerializeField] private Transform muzzle;
}

Explain a field in place

using GrayWolf.Gaze;
using UnityEngine;

public class AudioMix : MonoBehaviour
{
    [InfoBox("Values above 1 will clip on most output devices.", InfoMessageType.Warning)]
    [SerializeField] private float gain = 1f;

    [InfoBox("Read at start only, changing this at runtime does nothing.")]
    [SerializeField] private int channelCount = 2;
}

Value Box
InfoMessageType.None No icon
InfoMessageType.Info Information, the default when the argument is omitted
InfoMessageType.Warning Warning
InfoMessageType.Error Error

Show a value without letting it be edited

using GrayWolf.Gaze;
using UnityEngine;

public class Runtime : MonoBehaviour
{
    [ReadOnly]
    [SerializeField] private string buildId = "unset";

    private void Awake() => buildId = Application.buildGUID;   // still writable
}

The field is still serialized and still writable from script. [ReadOnly] only removes the Inspector as a way to change it. When the field should be editable under some conditions, use [DisableIf] instead.

Rename a field’s label

[LabelText("Rate (per second)")]
[SerializeField] private float spawnRate = 1f;

Replaces the label Unity would otherwise derive from the field name.

React when a value changes

using GrayWolf.Gaze;
using UnityEngine;

public class Light2D : MonoBehaviour
{
    [OnValueChanged(nameof(RebuildMesh))]
    [SerializeField] private int segments = 16;

    [OnValueChanged(nameof(OnRadiusChanged))]
    [SerializeField] private float radius = 1f;

    private void RebuildMesh()
    {
        // no parameters
    }

    private void OnRadiusChanged(float oldValue, float newValue)
    {
        Debug.Log($"radius {oldValue} -> {newValue}");
    }
}

The method takes either zero parameters, or exactly two of the field’s type (old value, new value). It may be private and may be declared on a base type. [OnValueChanged] is AllowMultiple, so a field can call more than one method.

It fires only on a direct edit through the Inspector, and not on undo/redo, not when script changes the field.

Clamp a vector component by component

using GrayWolf.Gaze;
using UnityEngine;

public class Bounds2D : MonoBehaviour
{
    // X in 0..8, Y in 0..8
    [VectorRange(0f, 0f, 8f, 8f)]
    [SerializeField] private Vector2 size = Vector2.one;

    // X, Y, Z each in 0..8
    [VectorRange(0f, 0f, 0f, 8f, 8f, 8f)]
    [SerializeField] private Vector3 offset = Vector3.one;

    // All four in 0..1, drawn as sliders
    [VectorRange(0f, 0f, 0f, 0f, 1f, 1f, 1f, 1f, true)]
    [SerializeField] private Vector4 weights = Vector4.one;

    // Works on the int vectors too
    [VectorRange(0f, 0f, 16f, 16f)]
    [SerializeField] private Vector2Int cell = Vector2Int.one;
}

Every overload takes all the minimums first, then all the maximums, with an optional trailing showSliders. The three shapes are 2-axis, 3-axis and 4-axis.

Applies to Vector2, Vector3, Vector4, Vector2Int and Vector3Int.
A Vector3 tagged with the 2-axis overload has a free Z.

Bound and tint a curve

using GrayWolf.Gaze;
using UnityEngine;

public class Falloff : MonoBehaviour
{
    // Time 0..1, value 0..1, default pale blue
    [CurveRange(0f, 1f, 0f, 1f)]
    [SerializeField] private AnimationCurve intensity = AnimationCurve.EaseInOut(0, 0, 1, 1);

    // Time 0..1, value -1..1, drawn in amber
    [CurveRange(0f, 1f, -1f, 1f, 1f, 0.72f, 0.2f)]
    [SerializeField] private AnimationCurve offset = AnimationCurve.Linear(0, 0, 1, 1);
}

The first four arguments are timeMin, timeMax, valueMin, valueMax. The optional tail is colorR, colorG, colorB, colorA, each 0 to 1, with alpha defaulting to 1. Omitting the colour gives the default (0.25, 0.75, 1, 1).

AnimationCurve fields only.

Serialized dictionaries

Since v1.0.0

With a searchbar and customizable column labels.

Unity doesn’t serialize Dictionary<TKey, TValue>. The usual workaround is two parallel lists and a rebuild step, which is easy to get out of sync. Gaze ships a dictionary that serializes, draws as a two-column table, and reads like a normal dictionary from code.

Usage

using GrayWolf.Gaze.Collections;
using UnityEngine;

public class LootTable : MonoBehaviour
{
    [SerializeField]
    private SerializedDictionary<string, GameObject> drops = new();

    private void Awake()
    {
        if (drops.TryGetValue("common", out var prefab))
            Instantiate(prefab);
    }
}

Building one from an existing dictionary

If you already have a Dictionary<TKey, TValue>, from a config file, a network response or a LINQ query, hand it to the constructor instead of adding entries one at a time:

var parsed = json.Deserialize<Dictionary<string, GameObject>>();
drops = new SerializedDictionary<string, GameObject>(parsed);

The entries are copied into the new dictionary, so adding or removing from one does not affect the other. The values themselves are not cloned: for UnityEngine.Object references and structs that is what you want, but if TValue is a mutable class, both dictionaries point at the same instances.

A null source is tolerated and gives you an empty dictionary.

Key and value types

Both TKey and TValue must be types Unity can serialize, or the contents won’t survive a domain reload: primitives, strings, enums, Unity’s own structs, UnityEngine.Object references, and your own [Serializable] classes and structs. Keys are matched with EqualityComparer<TKey>.Default, so a custom key type needs Equals/GetHashCode.

Keys must not be null. Add and the indexer setter throw ArgumentNullException.

What happens to duplicate keys

Unity’s serializer can’t enforce key uniqueness, so a hand-edited asset or a merge can produce two rows with the same key. When that happens:

  • The first occurrence wins. Later rows are dropped from the lookup. They stay in the serialized data, and stay visible in the Inspector, but reads never see them.
  • Count reports distinct keys, so it can be smaller than the number of rows shown in the table. Enumeration and CopyTo likewise yield distinct entries only.
  • At runtime, each offending key is logged once with Debug.LogWarning.
  • In the Inspector, the duplicate rows are tinted and an error box above the table names the keys.

If the two backing lists end up different lengths, which is the other thing a bad merge can do, the table draws the first n rows they agree on and warns you about the mismatch.

Rename the columns

[SerializedDictionary] attribute relabels the dictionary.

using System;
using GrayWolf.Gaze.Collections;
using UnityEngine;

public class Abilities : MonoBehaviour
{
    public enum AbilityType
    {
        None = -1,
        Fire,
        Water,
        Wind,
        Earth
    }

    [Serializable]
    public struct AbilityStats
    {
        public AbilityType abilityType;
        public float cooldown;
        public int manaCost;
        public string description;
    }

    [SerializedDictionary("Ability", "Cooldown")]
    [SerializeField]
    private SerializedDictionary<string, float> cooldowns = new();

    [SerializedDictionary("Ability", "Stats", nameof(AbilityStats.abilityType))]
    [SerializeField]
    private SerializedDictionary<string, AbilityStats> stats = new();
}

The third argument names a field on the value type whose contents title each row.

Editing the backing lists yourself

If you change the backing lists behind the instance’s back, through SerializedProperty or reflection as an editor script might, nothing marks the lookup stale, so tell it yourself:

drops.Invalidate();   // next read rebuilds from the serialized lists

Polymorphic fields

Since v1.0.0

A subclass picker for [SerializeReference] fields.

Pick a subclass

using System;
using UnityEngine;

[Serializable]
public abstract class Effect
{
    public float duration = 1f;
}

[Serializable]
public class Damage : Effect
{
    public int amount = 10;
}

[Serializable]
public class Slow : Effect
{
    public float multiplier = 0.5f;
}

public class Ability : MonoBehaviour
{
    [SerializeReference]
    private Effect onHit;
}

onHit draws a dropdown listing Damage and Slow. Choosing one creates an instance and the fields of that instance draw underneath, in a foldout.
It is important to give [Serializable] attribute to the base type (declared field type).

What the dropdown lists

The list is built from TypeCache.GetTypesDerivedFrom on the field’s declared type, filtered down to what Unity can actually create:

Excluded Why
Abstract types Cannot be instantiated
Generic type definitions No concrete type to construct
Types with no parameterless constructor Gaze constructs the instance with Activator.CreateInstance

A subclass missing from the list is nearly always the constructor rule. Add a public parameterless constructor alongside your other ones.

When a type rename breaks a reference

There is a Unity gotcha about [SerializeReference]:
A managed reference’s address is stored by class name, namespace and assembly. Rename the class, move it to another namespace, or move it to another assembly, and Unity can no longer find the type. The reference reads as null.

The picker above is how those references got assigned, so recovering them when a type moves is Gaze’s problem too. It draws an error box at the top of the Inspector when an object holds references that are no longer at their address:

2 missing SerializeReference types:
  Combat.Effects.Bleed (Assembly-CSharp) ×3
  Combat.Effects.Stun (Assembly-CSharp)

The data is still saved. Rename the type back, or add [MovedFrom] to the
renamed type to migrate it.

The box names each missing type with its assembly and counts the instances. Its right-click menu carries the recovery entries:

Entry Does
Copy Type Name Copies the full type names, one per line
Copy Serialized Data Copies the raw serialized JSON of every missing record
Clear Missing Records Drops the records from the object, once you are sure the values are gone for good

Verify Saved Data sweeps the open scenes for objects in this state, if you want to find them all at once.

Getting the data back

Renaming the class back to its old name restores every reference. To keep the new name, tag the type so Unity can follow the move:

using UnityEngine.Scripting.APIUpdating;

[MovedFrom(false, sourceClassName: "Bleed")]
[Serializable]
public class RenamedBleed : Effect
{
}

[MovedFrom(false, sourceClassName: "Stun")]
[Serializable]
public class StunWithADifferentName : Effect
{
}

Add the attribute before you refactor where you can. It is the only supported migration path, and Unity has had this on the issue tracker since 2019.

Two limits to know:

  • Gaze cannot mark the individual fields. SerializedProperty reports a missing managed reference identically to an empty one, so the report is per object rather than per field.
  • Orphaned records clear themselves, if the object can save. A missing record that no field points at any more disappears when the object is saved and reloaded. A component that has stopped saving never gets that far, which is what Troubleshooting covers.

Writing a custom drawer

Since v1.0.0

Creating your own drawers for types and decorators for attributes.

Gaze resolves one drawer per property and wraps it in a decorator for each attribute on the field. Both halves are open to extend: PropertyDrawer<T> renders a type, AttributeDrawer<T> decorates whatever would otherwise have rendered it.

Draw your own type

Drawers are discovered by their generic argument through Unity’s TypeCache.
A non-abstract, non-generic class with a parameterless constructor is enough.

Derive from PropertyDrawer<T>, where T is the declared field type, and override Draw:

// YourGame assembly
using System;

[Serializable]
public struct Interval
{
    public float min;
    public float max;
}
// YourGame.Editor assembly
using GrayWolf.Gaze.Editor;
using UnityEditor;
using UnityEngine;

internal sealed class IntervalDrawer : PropertyDrawer<Interval>
{
    private SerializedProperty _minProp;
    private SerializedProperty _maxProp;
    
    protected override void Initialize()
    {
        _minProp = Property.FindPropertyRelative(nameof(Interval.min));
        _maxProp = Property.FindPropertyRelative(nameof(Interval.max));
    }

    public override void Draw(GUIContent label)
    {
        using (var scope = new EditorGUI.ChangeCheckScope())
        {
            var edited = PropertyTreeGUI.Vector2Field(label, 
                new Vector2(_minProp.floatValue, _maxProp.floatValue));
            
            if (scope.changed)
            {
                _minProp.floatValue = edited.x;
                _maxProp.floatValue = Mathf.Max(edited.x, edited.y);
            }
        }
    }
}

Every Interval in the project now draws as one row with a guaranteed min <= max.

Four rules decide whether your drawer is the one that runs:

  • Matching is by exact type. PropertyDrawer<Base> does not draw a subclass of Base.
  • For an array or List<T> field, T is the element type. The collection itself keeps the built-in list drawer, and each element goes through yours.
  • A [CustomPropertyDrawer] for the same type wins, and the drawing falls back to that drawer.
  • Two PropertyDrawerBase<T> for the same T is a conflict. The first one found wins and the collision is logged as a warning.

Members you get from the base class

Member
Property The SerializedProperty this drawer is bound to
Children Drawers for the property’s child properties; empty for a primitive
Draw(GUIContent label) The one thing you must override
Initialize() Runs once after binding, before the first Draw
CollectMessages(List<GazeMessage>) Contributes message boxes above the property

Property is re-resolved from its path on every access, so it stays valid across the serialized object being rebuilt, and returns null once the target is gone. Children builds a fresh list per access, so read it into a local rather than indexing it repeatedly inside a loop.

Initialize is the place to cache anything derived from the property that won’t change.

Decorate an attribute

AttributeDrawer<T> wraps the drawer that would otherwise have rendered the field. You reach it through Inner, so you can draw around the field, change the GUI state it draws in, replace its label, or skip it entirely.

// YourGame assembly
using System;
using UnityEngine;

[AttributeUsage(AttributeTargets.Field)]
public sealed class EditModeOnlyAttribute : PropertyAttribute
{
}
// YourGame.Editor assembly
using GrayWolf.Gaze.Editor;
using UnityEngine;

internal sealed class EditModeOnlyDecorator : AttributeDrawer<EditModeOnlyAttribute>
{
    public override void Draw(GUIContent label)
    {
        using (new EditorGui.DisabledScope(Application.isPlaying))
        {
            Inner.Draw(label);
        }
    }
}

[EditModeOnly] now greys a field out during play mode. Two details:

  • Attribute carries the instance from the field, with whatever the user passed to its constructor. Cast it in Initialize, which runs after it is set.
  • Not calling Inner.Draw hides the property, which is exactly how ShowIf works.

An attribute that carries arguments is no different. Declare them as usual, and cast Attribute in Initialize to read them:

// YourGame assembly
using System;
using UnityEngine;

[AttributeUsage(AttributeTargets.Field)]
public sealed class WarnAboveAttribute : PropertyAttribute
{
    public readonly float Limit;

    public WarnAboveAttribute(float limit) => Limit = limit;
}

Override CollectMessages to contribute infoboxes without drawing them yourself.

Call base.CollectMessages(messages) unless you specifically mean to suppress the rest of the chain. For a decorator, the base call is what forwards to the drawer being decorated; skipping it silently drops every message below.

InfoMessageType is the same enum [InfoBox] uses: None, Info, Warning, Error.

A GazeMessage is a severity and a string:

// YourGame.Editor assembly
using System.Collections.Generic;
using GrayWolf.Gaze;
using GrayWolf.Gaze.Editor;
using UnityEditor;
using UnityEngine;

internal sealed class WarnAboveDecorator : AttributeDrawer<WarnAboveAttribute>
{
    private WarnAboveAttribute _attribute;

    protected override void Initialize()
    {
        _attribute = (WarnAboveAttribute) Attribute;
    }

    protected override void CollectMessages(List<GazeMessage> messages)
    {
        if (Property.propertyType == SerializedPropertyType.Float &&
            Property.floatValue > _attribute.Limit)
        {
            messages.Add(new GazeMessage(
                InfoMessageType.Warning,
                $"Above the recommended maximum of {_attribute.Limit}."));
        }

        base.CollectMessages(messages);
    }

    public override void Draw(GUIContent label) => Inner.Draw(label);
}
// YourGame assembly
using UnityEngine;

public class Foo : MonoBehaviour
{
    [SerializeField]
    [WarnAbove(12)]
    private float attackRate; 
}

One trap worth knowing

An attribute with no drawer hands the whole property back to Unity’s default drawing. If you write an attribute purely as configuration for something else, it still needs a drawer, even an empty one whose Draw just forwards to Inner:

// YourGame assembly
using System;
using UnityEngine;

[AttributeUsage(AttributeTargets.Field)]
public class JustToTagAttribute : PropertyAttribute
{
}
// YourGame.Editor assembly
using GrayWolf.Gaze.Editor;
using UnityEngine;

public class JustToTagDecorator : AttributeDrawer<JustToTagAttribute>
{
    public override void Draw(GUIContent label)
    {
        Inner.Draw(label);
    }
}

Drawing controls

PropertyTreeGUI exposes the same value fields the built-in drawers use, so your drawer lines up with the rest of the Inspector without hand-measuring rects:

public static string  TextField(GUIContent label, string value, float height, bool isDelayed = false)
public static string  TextArea(GUIContent label, string value, float height)
public static int     IntField(GUIContent label, int value, bool isDelayed = false,
                               bool isSlider = false, int? minValue = null, int? maxValue = null)
public static float   FloatField(GUIContent label, float value, bool isSlider = false,
                               float? minValue = null, float? maxValue = null)
public static Vector2 Vector2Field(GUIContent label, Vector2 value)
public static Vector3 Vector3Field(GUIContent label, Vector3 value)
public static Vector4 Vector4Field(GUIContent label, Vector4 value)
public static Vector2Int Vector2IntField(GUIContent label, Vector2Int value)
public static Vector3Int Vector3IntField(GUIContent label, Vector3Int value)

Dragging the label to change a number/vector is built into numeric fields.

Grouping and layout:

Call For
BeginHorizontalLayout(label, out labelRect, style, options) / EndHorizontalLayout() A labelled row. labelRect is what you hit-test for a label drag or context click
BeginVerticalLayout(label, out labelRect, style, options) / EndVerticalLayout() A labelled block. Label width and indent are pushed for the contents and restored on end
BeginFadeGroup(float t) / EndFadeGroup() Foldout animation. Pass raw 0..1 progress, which is eased internally. Always call EndFadeGroup, including when BeginFadeGroup returned false
BeginListItem(int row, evenStyle, oddStyle) / EndListItem() Alternating row backgrounds
BeginMeasuring(style) / Rect EndMeasuring() Learn the rect a block actually occupied. Returns default during Layout

And the GUI-state scopes on EditorGui:

  • new EditorGui.DisabledScope(bool disabled) greys out and blocks input.
  • new EditorGui.MixedValueScope(bool mixed) draws the mixed value indicator (dash character) for a multi-object selection that disagrees. Pass Property.hasMultipleDifferentValues to match the built-in drawers.
  • EditorGui.CurrentIndentAmount is the width in pixels the current indent level is worth, for reserving leading space by hand inside a flattened layout group.

Drawing a tree outside the Inspector

PropertyTree and PropertyTreeGUI.DrawTree are public, so a custom editor or an EditorWindow can render an object the way Gaze would:

using GrayWolf.Gaze.Editor;
using UnityEditor;
using UnityEngine;
using Object = UnityEngine.Object;

public class RigWindow : EditorWindow
{
    [SerializeField] private Object target;

    private SerializedObject _serializedObject;
    private PropertyTree _tree;

    [MenuItem("Window/Editor Tools/RigWindow")]
    public static void ShowWindow()
    {
        EditorWindow.GetWindow(typeof(RigWindow));
    }
    
    private void OnGUI()
    {
        target = EditorGUILayout.ObjectField(target, typeof(Object), true);

        if (target == null)
            return;

        if (_serializedObject == null || _serializedObject.targetObject != target)
        {
            _serializedObject = new SerializedObject(target);
            _tree = null;
        }

        _tree ??= new PropertyTree(_serializedObject);

        _serializedObject.Update();
        PropertyTreeGUI.DrawTree(_tree);
        _serializedObject.ApplyModifiedProperties();
        this.TryRepaint();
    }
}

Right-click menus

Since v1.0.0

The property clipboard, and serving your own context menu from a drawer.

Right-clicking a property in a Gaze Inspector opens a menu served by the drawer under the pointer. Several built-in drawers offer one, including colors, enums, gradients, object references, masks, lists, dictionaries, toggles, foldouts and [SerializeReference] fields, and a drawer of your own can serve its own.

The property clipboard

PropertyClipboard is the editor-wide clipboard behind those Copy and Paste entries, shared across every Inspector window.

  • Copying captures the whole subtree, including nested objects, collection contents and managed references included.
  • Paste is offered only when the declared field types match exactly. A Vector3 cannot be pasted into a Vector2, and a subclass cannot be pasted into a field declared as its base.

Add copy/paste to your own menu

PropertyClipboard.AddContextMenu is the only public entry point, and it exists so a third-party menu can match the built-in ones:

public static void AddContextMenu(
    GenericMenu menu,
    SerializedProperty property,
    string copyText = "Copy",
    string pasteText = "Paste")

Both entries are always added, greyed out when unavailable, so the menu keeps a stable shape rather than changing height depending on what is on the clipboard. A null menu or a null property is a no-op.

Serve a menu from a drawer

Implement IContextMenuProvider on the drawer. It has two members:

Rect ContextClickArea { get; }
GenericMenu Provide(out Rect highlightArea);

Providers are registered automatically when the tree resolves the drawer. There is nothing to call. Extending the drawer from Writing a custom drawer:

// YourGame.Editor assembly
using GrayWolf.Gaze.Editor;
using UnityEditor;
using UnityEngine;

internal sealed class IntervalDrawer : PropertyDrawer<Interval>, IContextMenuProvider
{
    private Rect _rowArea;

    public Rect ContextClickArea => _rowArea;

    private SerializedProperty _minProp;
    private SerializedProperty _maxProp;
    
    protected override void Initialize()
    {
        _minProp = Property.FindPropertyRelative(nameof(Interval.min));
        _maxProp = Property.FindPropertyRelative(nameof(Interval.max));
    }

    public override void Draw(GUIContent label)
    {
        PropertyTreeGUI.BeginMeasuring();

        using (var scope = new EditorGUI.ChangeCheckScope())
        {
            var edited = PropertyTreeGUI.Vector2Field(label,
                new Vector2(_minProp.floatValue, _maxProp.floatValue));

            if (scope.changed)
            {
                _minProp.floatValue = edited.x;
                _maxProp.floatValue = Mathf.Max(edited.x, edited.y);
            }
        }

        var measured = PropertyTreeGUI.EndMeasuring();

        // Rects only exist once laid out, so record it on Repaint and leave it alone otherwise.
        if (Event.current.type == EventType.Repaint)
            _rowArea = measured;
    }

    public GenericMenu Provide(out Rect highlightArea)
    {
        highlightArea = _rowArea;

        var menu = new GenericMenu();
        PropertyClipboard.AddContextMenu(menu, Property);
        menu.AddSeparator(string.Empty);
        menu.AddItem(new GUIContent("Reset to 0..1"), false, ResetToUnit);
        return menu;
    }

    private void ResetToUnit()
    {
        var property = Property;
        property.FindPropertyRelative(nameof(Interval.min)).floatValue = 0f;
        property.FindPropertyRelative(nameof(Interval.max)).floatValue = 1f;
        property.serializedObject.ApplyModifiedProperties();
    }
}

ContextClickArea

The region, in the Inspector’s GUI space, that counts as a right-click on this drawer, usually the label row, or the toolbar for a collection.

Rects are only meaningful once laid out, so assign it during a Repaint pass and leave it alone otherwise, as the example does.

Provide

Called on the click itself, not on the frame the menu opens.

highlightArea is the colored (amber by default) region on the left while the menu is open. Set it to the whole block the menu applies to, which for a foldout or a list is wider than ContextClickArea. Returning null swallows the click without showing anything.

When areas overlap

Providers are consulted in registration order, and the first whose ContextClickArea contains the pointer wins. In the case of a nested drawer whose area overlaps its parent’s, resolves to the innermost one (child).

Troubleshooting

Since v1.0.0

When data goes missing, what Gaze reports and how to get it back.

Two things can quietly cost you work. Neither is caused by the Inspector, but the Inspector is where you would notice, so it is where the report belongs.

A component that stops saving

Unity can leave a component reporting healthy through every API it exposes while still writing stale data to disk. The scene saves, every other object in it writes correctly, and that one component keeps its old values. Nothing is logged, and the Inspector goes on showing what you typed, so the loss only surfaces after a domain or scene reload.

Nothing about it depends on Gaze. It happens under the built-in Inspector too, just with nothing to tell you.

It is checked here because an Inspector’s whole job is to tell you what an object holds. One that shows a value which never reached the file is getting that job wrong, whoever dropped the data.

The report

An error box appears on the component:

This component is not being saved.

Unity wrote the scene and skipped these fields:
  onHit
  notes

Anything you change here will be lost. Right-click and choose Rebuild Component
to replace it with a working one, keeping its values and every reference to it.

The same finding goes to the Console with the component as context, so double-clicking the entry selects it.

The check runs after a save and never before. Before one, a field you have just added to a script is legitimately on the object and missing from the file, which is simply unsaved. Surviving a save is what makes it a failure: Unity rewrote the file and skipped the field anyway.

It only looks at what you edited since the last save, so the cost tracks the size of your change rather than the size of the scene. Nothing is walked, and nothing happens while the Inspector is drawing.

Rebuilding the component

Right-click the box and choose Rebuild Component. Gaze adds a fresh component, copies every serialized value onto it, repoints everything that referenced the old one, removes the old one, and moves the replacement back to the same position in the Inspector. The whole thing is one undo step.

Deleting the component and adding it back by hand performs the same repair and quietly breaks every reference to it, because the replacement gets a new file id and each field pointing at the old one reads as None afterwards. Rebuild collects those references first and restores them.

For a component in a scene that repoint is complete rather than best effort: Unity does not allow an asset to reference a scene object, so the loaded scenes are the entire reference surface.

Two cases are refused rather than half handled:

Refused Why
A component on a prefab asset References reach it from other prefabs and from every instance in every scene
A component on a prefab instance Rebuilding would break the link to the prefab. Open the prefab, or unpack the instance first

A SerializeReference type that moved

Unity stores a managed reference by class name, namespace and assembly. Rename the type, move it to another namespace, or move it to another assembly, and it can no longer read the record. The reference goes null.

An error box names the types it cannot find, and its right-click menu can drop the dead records once the values are gone for good. The type picker Gaze puts on those fields is how the references were assigned in the first place, which is why the recovery lives here.

Polymorphic fields covers it in full, including migrating a renamed type with [MovedFrom].

Checking on demand

Tools > Gray Wolf > Gaze > Settings, Troubleshooting tab, Verify Saved Data. It saves the open scenes first, then checks every component in them, and reports both problems above.

This is the sweep the automatic check deliberately avoids, so it takes as long as the scene is big. It reports progress and can be cancelled.

Turning it off

Tools > Gray Wolf > Gaze > Settings, Troubleshooting tab, Check after saving. Off disables the checks, the error boxes and the recovery entries.
